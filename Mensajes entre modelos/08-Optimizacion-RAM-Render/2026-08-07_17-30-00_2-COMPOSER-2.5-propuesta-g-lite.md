# Propuesta: Estrategia G-Lite (GraphQL-first + poda DOM + reciclado adaptativo)

## Resumen ejecutivo

El contenedor arranca con **477/512 MB** y el scroll agrega DOM hasta OOM. Las micro-optimizaciones (headless, bloqueo imágenes, flags) ahorran **<35 MB** — insuficiente.

**Propuesta Composer 2.5:** handler paralelo **`scroll-anon-graphql.ts`** (G-Lite) que:

1. **Extrae comentarios vía GraphQL** durante el scroll (no recorre todo el DOM cada iteración).
2. **Poda nodos DOM** ya capturados para frenar el crecimiento del renderer.
3. **Recicla cada 8 iteraciones** + cuando RAM ≥ 85% del cgroup (posts chicos incluidos).
4. **Baja Node heap a 256 MB** (libera margen en cgroup).
5. **Auto-tier de navegador** en Render: chromium (≤300 comentarios) → chrome headless (>300) → Apify fallback.

La **G clásica no se toca** (flujo estable local/visible).
